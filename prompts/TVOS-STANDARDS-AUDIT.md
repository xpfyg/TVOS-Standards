# tvOS 规范合规审计提示词

你是一名资深 Apple tvOS 产品设计师、SwiftUI 工程师和质量负责人。请审计当前仓库是否符合项目规则与 tvOS 规范。先检查规则文件，再检查代码与资源；不要在未经确认的情况下大范围修改文件。

## 必读规范

- `AGENTS.md`
- `TVOS-PRODUCT-DESIGN-BASELINE.md`
- `TVOS-DESIGN-SYSTEM.md`
- `TVOS-INTERACTION-SPEC.md`
- `TVOS-RELEASE-CHECKLIST.md`

若某文件缺失，请列为审计限制，不要假装读取过。

## 审计原则

1. 先只读审计，未经明确授权不要直接修改代码。
2. 每个问题都要提供证据：文件路径、相关符号/代码片段或可复现步骤。
3. 区分已确认问题、潜在风险和无法验证项。
4. 不得仅凭静态阅读宣称构建、测试、真机体验或 App Store 审核通过。
5. 优先报告影响核心流程、焦点可用性、崩溃、数据安全、性能和发布阻塞的问题。
6. 不要为了符合抽象规则而建议无意义重构。
7. Apple API、系统行为和审核要求如存在版本差异，标明需要对照官方文档验证。

## 审计范围

- 产品设计基线一致性
- 视觉层级、布局、字体、颜色与设计 token
- Siri Remote 焦点、方向导航、页面返回与弹窗行为
- SwiftUI 状态所有权、组件边界、异步任务和错误处理
- 加载/空/失败/离线状态
- 播放器状态、自动连播、字幕、竖屏视频适配（若适用）
- 性能、内存、动画和图片/视频缓存
- VoiceOver、可访问性与国际化
- 隐私、权限、日志与第三方依赖
- 构建、测试、签名和商店发布准备度

## 输出格式

### 1. 总体结论
- 状态：PASS / FAIL / BLOCKED / NOT RUN
- 风险等级：P0 / P1 / P2 / P3
- 审计范围与限制

### 2. 问题列表
每项包含：
- ID 与严重程度
- 状态：已确认 / 潜在风险 / 无法验证
- 证据（路径、符号、步骤）
- 违反的规则
- 用户影响
- 建议修复方案
- 建议验证方法

### 3. 按阶段的修复计划
按 P0 → P3 排序，优先给出最小改动路径。

### 4. 验证清单
列出需要执行的构建、测试、模拟器/真机操作和商店检查；没有实际执行的项目必须标记为 NOT RUN 或 BLOCKED。

### 5. 不要做的事
- 不要自动重写整个项目。
- 不要修改产品品牌或信息架构。
- 不要把未执行的检查标记为通过。
- 不要省略证据或把推测写成事实。

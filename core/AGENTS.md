# tvOS 项目 AI 协作核心规范

## 1. 工作原则

1. 先阅读项目说明、现有架构、`TVOS-PRODUCT-DESIGN-BASELINE.md` 及三份 tvOS 规范，再修改代码。
2. 优先理解并延续现有架构。不要为了局部功能重写整个模块或无必要地引入新依赖。
3. 先给出简短实施计划，明确涉及页面、状态、数据流、焦点、测试与风险；复杂任务按阶段推进。
4. 不要把“代码已生成”描述成“功能已验证”。只有实际运行过的构建、测试或检查才能标记为通过。
5. 未经用户要求，不删除数据、重置项目、改写历史或执行不可逆操作。
6. 对不确定的 Apple API、系统版本行为、审核政策和第三方 SDK，先查项目依赖或官方文档，不要臆造 API。

## 2. 规范读取

开始工作前检查以下文件是否存在，并按任务相关性读取：
- `TVOS-PRODUCT-DESIGN-BASELINE.md`
- `TVOS-DESIGN-SYSTEM.md`
- `TVOS-INTERACTION-SPEC.md`
- `TVOS-RELEASE-CHECKLIST.md`

若缺失，说明缺失项；不要假装已遵循未读取的规范。

## 3. 实施流程

1. **勘察**：识别入口、导航结构、状态管理、资源、播放器、网络层和测试方式。
2. **方案**：给出最小改动方案与验收标准。
3. **实现**：遵循 SwiftUI 组件边界、状态所有权、焦点稳定性和设计 token。
4. **验证**：执行可用的构建、测试、静态检查；对无法执行的项目标记 BLOCKED，并说明原因。
5. **复核**：检查视觉层级、焦点路径、加载/错误/空状态、无障碍、性能和回归风险。
6. **交付**：列出变更文件、关键实现、测试命令及真实结果、未解决问题。

## 4. SwiftUI 代码质量

- 遵循项目已有的 Swift 版本、命名、目录、并发与架构约定。
- 将可复用 UI 抽成语义清晰的组件；不要为了抽象而抽象。
- 视图只负责展示与用户交互；业务逻辑、数据访问和播放协调应放在合适的模型/服务层。
- 明确 `@State`、`@Observable`、`@StateObject`、`@Environment` 等状态所有权，避免重复来源和不必要重绘。
- 避免超大 `body`、重复魔法数字、散落的颜色与尺寸常量。
- 异步任务应处理取消、重复请求、错误和主线程 UI 更新。
- 新增依赖前说明收益、替代方案、维护风险与体积影响。

## 5. tvOS 专项

- Siri Remote 的焦点移动是核心交互，不是鼠标悬停的简单替代。
- 所有可操作元素必须可聚焦，焦点状态必须清晰，并验证方向键导航。
- 不要只依赖颜色传达状态；考虑可读性、动态类型可用性和辅助功能。
- 焦点更新、列表刷新和异步加载不得导致焦点无故丢失或跳转。
- 页面返回后尽可能恢复用户之前的上下文与焦点。
- 长时间操作必须提供可见反馈，网络失败必须提供可理解的恢复路径。
- 播放器必须覆盖加载、播放、暂停、缓冲、失败、结束、切集和下一集等状态。
- 针对竖屏内容、字幕、安全区域、遥控器操作与系统播放控制做专项验证。

## 6. 设计纪律

- 先读取产品设计基线，不擅自改变品牌定位。
- 使用 `TVOS-DESIGN-SYSTEM.md` 中的 token；新增 token 要解释原因并集中管理。
- 不把所有页面都做成相同的卡片网格；布局服务于内容层级和电视观看距离。
- 先解决信息架构、比例、层级、留白和焦点，再做装饰效果。
- 动效必须帮助理解状态或空间关系，避免无意义的持续动画和过度模糊。
- 资源必须有正确的尺寸、裁切、安全区和失败占位方案。

## 7. 质量门禁

交付前逐项对照 `TVOS-RELEASE-CHECKLIST.md`。报告状态只能使用：
- `PASS`：已实际验证并有证据。
- `FAIL`：已验证且不符合要求。
- `BLOCKED`：无法验证，说明阻塞原因。
- `NOT RUN`：尚未执行。
- `N/A`：明确不适用，并解释理由。

## 8. 最终回复格式

- **完成内容**
- **修改文件**
- **验证结果**：命令、结果、未执行项目
- **风险与遗留问题**
- **下一步建议**

不要声称运行了实际上没有运行的测试，也不要仅凭代码阅读就宣称 UI 已在 Apple TV 真机上通过。
